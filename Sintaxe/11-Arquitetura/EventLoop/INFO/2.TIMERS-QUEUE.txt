╔══════════════════════════════════════════════════════════════════╗
║  Event Loop — Fase Timers (setTimeout / setInterval)             ║
╚══════════════════════════════════════════════════════════════════╝


┌─ Visão geral ────────────────────────────────────────────────────┐
│                                                                   │
│  O setTimeout() e setInterval() NÃO usam o Thread Pool.          │
│  Eles são agendados diretamente no Event Loop da libuv, que      │
│  gerencia timers em uma estrutura de heap (min-heap) ordenada    │
│  por tempo de expiração.                                          │
│                                                                   │
└───────────────────────────────────────────────────────────────────┘


┌─ Fluxo da operação ──────────────────────────────────────────────┐
│                                                                   │
│    1. O código JS chama setTimeout(callback, delay)             │
│    2. A libuv registra o timer em seu min-heap interno com o    │
│       timestamp de expiração (agora + delay)                      │
│    3. O Event Loop continua executando outras fases               │
│       (poll, check, etc.)                                         │
│    4. Quando o loop chega na fase timers, verifica quais          │
│       timers expiraram (timestamp <= tempo atual)                 │
│    5. Os callbacks expirados são movidos para a Call Stack        │
│       e executados                                                │
│                                                                   │
└───────────────────────────────────────────────────────────────────┘


┌─ Precisão dos timers ─────────────────────────────────────────────┐
│                                                                   │
│    • O delay é um mínimo, não uma garantia exata                  │
│    • O callback só executa quando o loop alcança a fase timers    │
│    • Se o loop estiver bloqueado em código síncrono ou I/O        │
│      pesado, o timer pode disparar depois do delay especificado   │
│    • A partir do Node.js 20 (libuv 1.45+), timers são executados  │
│      estritamente após a fase poll terminar                       │
│                                                                   │
└───────────────────────────────────────────────────────────────────┘


┌─ Interação com a fase Poll ───────────────────────────────────────┐
│                                                                   │
│    • Quando há timers pendentes, a fase poll não espera           │
│      indefinidamente por I/O — ela calcula quanto tempo falta     │
│      para o próximo timer                                         │
│    • A libuv passa esse timeout para o SO (epoll / kqueue / IOCP) │
│    • O loop acorda no máximo quando o timer expira, mesmo que     │
│      o I/O ainda não tenha terminado                              │
│                                                                   │
└───────────────────────────────────────────────────────────────────┘


┌─ Fluxo de execução do setTimeout() ──────────────────────────────┐
│                                                                   │
│                    ┌──────────────────────┐                       │
│                    │      Código JS       │                       │
│                    │ setTimeout(fn, 200)  │                       │
│                    └──────────┬───────────┘                       │
│                               │                                   │
│                               ▼                                   │
│                    ┌──────────────────────┐                       │
│                    │   V8 (Call Stack)    │                       │
│                    └──────────┬───────────┘                       │
│                               │                                   │
│                               ▼                                   │
│                    ┌──────────────────────┐                       │
│                    │     libuv (Node)     │                       │
│                    │ Registra timer no    │                       │
│                    │ min-heap (now + 200) │                       │
│                    └──────────┬───────────┘                       │
│                               │                                   │
│                               ▼                                   │
│        ┌────────────────────────────────────────────────────┐     │
│        │         Event Loop (libuv) — ciclo contínuo        │     │
│        │                                                      │     │
│        │ ► timers (verifica timers expirados)                 │     │
│        │   ┌──────────────────────────────────────────────┐   │     │
│        │   │ Min-heap de timers:                          │   │     │
│        │   │   [timer: 200ms]  ← menor timestamp no topo  │   │     │
│        │   │   [timer: 500ms]                             │   │     │
│        │   │   [timer: 1000ms]                            │   │     │
│        │   └──────────────────────────────────────────────┘   │     │
│        │                                                      │     │
│        │   • Pop timers com timestamp <= tempo atual          │     │
│        │   • Enfileira callbacks para execução                │     │
│        │                                                      │     │
│        │   pending callbacks                                    │     │
│        │   idle / prepare                                       │     │
│        │   poll (I/O de rede, arquivos, etc.)                   │     │
│        │     → Se há timers pendentes, poll espera no máximo    │     │
│        │       até o próximo timer expirar                      │     │
│        │   check                                                  │     │
│        │   close callbacks                                        │     │
│        └──────────────────────┬─────────────────────────────┘     │
│                               │                                   │
│                               ▼                                   │
│                    ┌──────────────────────┐                       │
│                    │   V8 (Call Stack)    │                       │
│                    │ Callback do timer    │                       │
│                    │ é executado          │                       │
│                    └──────────┬───────────┘                       │
│                               │                                   │
│                               ▼                                   │
│                    ┌──────────────────────┐                       │
│                    │ console.log(...)     │                       │
│                    │ ou outra lógica JS   │                       │
│                    └──────────────────────┘                       │
│                                                                   │
└───────────────────────────────────────────────────────────────────┘
