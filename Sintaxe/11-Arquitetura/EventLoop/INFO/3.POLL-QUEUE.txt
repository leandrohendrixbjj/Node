
╔══════════════════════════════════════════════════════════════════╗
║  Event Loop — Fase de POLL (I/O, rede, arquivos)                 ║
╚══════════════════════════════════════════════════════════════════╝

┌─ O que é POLL? ──────────────────────────────────────────────────┐
│                                                                  │
│  POLL é a fase em que o Event Loop *espera* e *consome*          │
│  conclusões de operações assíncronas ligadas a I/O:              │
│                                                                  │
│    • rede (HTTP, TCP, UDP — módulos http, net, dgram)            │
│    • sockets em geral (conexão, dados recebidos, escrita)        │
│    • muitas operações de fs assíncrono (readFile, writeFile, …)  │
│                                                                  │
│  O libuv pergunta ao SO (epoll/kqueue/IOCP, etc.) quais           │
│  descritores estão prontos; quando algo “acontece”, o callback  │
│  correspondente fica elegível para rodar na fase de poll.        │
│                                                                  │
│  👉 Rede costuma ser I/O “direto” no SO. Já parte do fs          │
│     pode usar *thread pool* interno, mas o resultado ainda        │
│     volta ao loop e o callback roda como tarefa assíncrona       │
│     (mesma ideia: JS não bloqueia enquanto isso acontece).       │
│                                                                  │
│  Depois de POLL vem a fase CHECK (setImmediate) — ordem           │
│  diferente de timers; não confunda as duas filas.                │
│                                                                  │
└──────────────────────────────────────────────────────────────────┘

┌─ O fluxo (do pedido até o callback) ─────────────────────────────┐
│                                                                  │
│        V8 (ex.: http.get, fs.readFile, socket.on('data'))         │
│                │                                                 │
│                ▼                                                 │
│        Node/libuv registra operação no SO ou no pool             │
│                │                                                 │
│                ▼                                                 │
│        ⏳ trabalho fora do Call Stack (rede / disco / threads)   │
│                │                                                 │
│                ▼                                                 │
│        POLL — evento “pronto” (dados, arquivo lido, etc.)          │
│                │                                                 │
│                ▼                                                 │
│        EVENT LOOP (fase POLL executa callbacks de I/O)            │
│                │                                                 │
│                ▼                                                 │
│        CALL STACK (executa o callback)                           │
│                                                                  │
└──────────────────────────────────────────────────────────────────┘

┌─ Exemplo: servidor HTTP + log ───────────────────────────────────┐
│                                                                  │
│  const http = require('http');                                   │
│                                                                  │
│  const server = http.createServer((req, res) => {                │
│    res.end('ok');                                                │
│    console.log('Respondeu');                                     │
│  });                                                             │
│                                                                  │
│  server.listen(3000, () => {                                     │
│    console.log('Escutando');                                     │
│  });                                                             │
│                                                                  │
│  Quando um pedido chega, o SO/libuv sinaliza dados no socket;    │
│  a fase poll agenda o handler quando a stack estiver livre.      │
│                                                                  │
└──────────────────────────────────────────────────────────────────┘

┌─ Exemplo realista: atraso por BLOQUEIO (CPU / while) ─────────────┐
│                                                                  │
│  Se o arquivo já estiver pronto mas o JS estiver em um loop       │
│  síncrono longo, o callback de fs.readFile só roda depois.         │
│                                                                  │
│  Exemplo:                                                        │
│                                                                  │
│    const fs = require('fs');                                     │
│                                                                  │
│    fs.readFile(__filename, () => {                                │
│      console.log('Arquivo lido');                                 │
│    });                                                           │
│                                                                  │
│    // Bloqueia por ~3 segundos                                   │
│    const start = Date.now();                                     │
│    while (Date.now() - start < 3000) {}                          │
│                                                                  │
│    console.log('Fim');                                           │
│                                                                  │
│  Saída esperada (aproximada):                                    │
│    Fim                                                           │
│    Arquivo lido                                                  │
│                                                                  │
│  Por quê?                                                        │
│    • O Event Loop não avança enquanto o Call Stack está ocupado  │
│    • A leitura pode terminar cedo, mas o callback de poll        │
│      só executa quando o loop puder processá-lo                 │
│                                                                  │
└──────────────────────────────────────────────────────────────────┘
