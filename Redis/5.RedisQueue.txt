1.Redis como fila: 
  - Redis não possui uma estrutura chamada Queue. 
  - Nós usamos principalmente uma List do Redis para implementar uma fila.
  - Muito simples: Você consegue criar uma fila usando operações extremamente simples do Redis.
  - Muito rápida: O Redis mantém os dados principalmente em memória.

  Conceitualmente:

          PRODUTOR
              │
              │ coloca item
              ▼
      ┌──────────────────────┐
      │       REDIS          │
      │                      │
      │      minha-fila      │
      │                      │
      │ [A] [B] [C] [D]      │
      │                      │
      └──────────┬───────────┘
                │
                │ retira item
                ▼
            CONSUMIDOR

2. Comandos

  - LPUSH: adiciona um elemento no lado esquerdo (início) de uma lista Redis.
  - RPUSH: adiciona um elemento no lado direito (final) de uma Redis List.
  
  - LPOP: remove e retorna o primeiro elemento do lado esquerdo de uma Redis List.
  - RPOP: remove um elemento no lado direito (final) de uma Redis List.

  - BLPOP: o mesmo que o LPOP, mas com uma diferença muito importante para uma Redis: Se a fila estiver vazia, o consumer fica aguardando 
           em vez de receber nil imediatamente. BLPOP  →  aguarda  →  mensagem chegou  →  processa  →  BLPOP novamente

  - BRPOP: É o equivalente ao BLPOP, mas remove o elemento do lado direito da Redis List.     

3. Arquitetura de uma Redis Queue      

    - LPUSH/RPUSH são normalmente utilizados pelo PRODUCER  para adicionar mensagens.
    - POP/RPOP/BLPOP/BRPOP são normalmente utilizados pelo CONSUMERS para removê-las.

  Importante:

    - LPOP / RPOP → consumidor consulta e remove imediatamente.
    - BLPOP / BRPOP → consumidor espera bloqueado até existir uma mensagem. 


4. Vários consumidores            

             FILA

    ▼         ▼         ▼
  Worker    Worker    Worker
    1         2         3


5. Desvantagens

  - A fila não é uma garantia de processamento.
  - A mensagem pode ser removida da fila antes de terminar o processamento.
  - Você precisa pensar em requeue, retry ou DLQ

      Redis
      │
      ▼
    Worker
      │
      │ pegou mensagem
      ▼
    PROCESSANDO
      │
      X
      │
      └── Worker morreu

  - Uma fila Redis pode acumular muitas mensagens: Isso significa que a fila pode consumir bastante memória.
  - Mensagens grandes são problemáticas

  - Portanto, é necessário pensar em:
      tamanho das mensagens;
      quantidade acumulada;
      tempo de retenção;
      comportamento quando o Redis fica sem memória.   

  - Redis Queue baseada em List é muito boa quando queremos: um mecanismo simples, rápido e de baixa latência para distribuir trabalhos 
    entre produtores e consumidores.     

6. TTL

  - Uma fila pode ser representada por uma chave Redis, e essa chave aponta para uma List:

        Redis
          │
          └── "fila:emails"          ← chave
                    │
                    ▼
                List
                    │
              ┌────┬────┬────┐
              ▼    ▼    ▼    ▼
              msg1 msg2 msg3 msg4

  - E o TTL pertence à chave:

    Importante: uma list sem mensagem: o Redis remove a chave da List, porque uma List vazia não é mantida em memória.

      "fila:emails"
          │
          ├── List
          │    ├── msg1
          │    ├── msg2
          │    └── msg3
          │
          └── TTL = 3600s
