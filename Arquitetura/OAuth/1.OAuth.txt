  1 · O QUE É OAUTH?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Protocolo de autorização que permite delegar acesso a uma aplicação
sem compartilhar diretamente as credenciais do usuário.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  2 · O QUE RESOLVE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Imagine uma conta no Google. Uma abordagem insegura seria passar usuário
e senha do Google para outro aplicativo. Nesse caso, o app teria as
credenciais e poderia usá-las para acessar a conta.

Com OAuth, isso não acontece. A aplicação recebe uma autorização limitada,
não a senha.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  3 · FLUXO SIMPLIFICADO
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  1. Usuário
        │  acessa o site
        ▼
  2. Sua aplicação
        │  redireciona para o Google
        ▼
  3. Google
        │  usuário autentica e autoriza
        ▼
  4. Google
        │  devolve o Authorization Code
        ▼
  5. Sua aplicação
        │  troca o code por tokens
        ▼
  6. Google
        ├── Access Token
        └── ID Token (OIDC)
        ▼
  7. Sua aplicação
        │  cria a própria sessão
        ▼
  8. Usuário autenticado

A aplicação não recebe a senha do usuário. Ela recebe um Access Token:
uma autorização delegada para acessar determinados recursos.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  4 · ACCESS TOKEN
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Representa autorização.

  Access Token = posso acessar recursos

                    Access Token
                         │
                         ▼
        "Esta aplicação está autorizada
         a acessar determinado recurso
         em nome deste usuário."


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  5 · ID TOKEN
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Representa a identidade do usuário. É um JWT e pode conter claims como:

  {
    "iss":   "https://accounts.google.com",
    "sub":   "123456789",
    "email": "usuario@gmail.com",
    "name":  "João",
    "aud":   "minha-aplicacao"
  }


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  6 · IMPORTANTE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

O Access Token não é um token de sessão. São conceitos diferentes:

  ┌────────────────┬──────────────────────────────────────────────────────────┐
  │ Conceito       │ Papel                                                    │
  ├────────────────┼──────────────────────────────────────────────────────────┤
  │ Access Token   │ Autoriza acesso a recursos protegidos (APIs)             │
  │ ID Token       │ Contém as informações de identidade do usuário           │
  │ Sessão         │ Identifica o usuário logado na sua aplicação             │
  └────────────────┴──────────────────────────────────────────────────────────┘

  8 · ALEGORIA: O HOTEL
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

OAuth funciona como um hotel: você faz a reserva e recebe um cartão
de acesso.

  ┌──────────────────────────┬──────────┐
  │ Área                     │ Acesso   │
  ├──────────────────────────┼──────────┤
  │ Quarto 302               │    ✓     │
  │ Academia                 │    ✓     │
  │ Piscina                  │    ✓     │
  │ Quarto 401               │    ✗     │
  │ Área administrativa      │    ✗     │
  └──────────────────────────┴──────────┘

Você não recebe a chave mestra do hotel. O cartão tem permissões
específicas e validade limitada.
