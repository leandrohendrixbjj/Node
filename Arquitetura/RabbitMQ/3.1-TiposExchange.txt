Direct Exchange

  - Entrega apenas para filas cuja Binding Key seja igual à Routing Key.
  - É a mais simples.
  - Bom para work queue: 1 fila + N consumers (distribuição de tarefas).

  Exemplo:

      Routing Key = orders.created
            │
            ▼
      Binding     = orders.created
            │
            ▼
          Queue


Fanout Exchange

  - Ignora a Routing Key.
  - Tudo que chega é enviado para todas as filas ligadas.
  - Muito usada para: broadcast, notificações e cache.

  Exemplo:

                Fanout
             /    │    \
            ▼     ▼     ▼
        Queue A  Queue B  Queue C


Topic Exchange

  - É a mais usada.
  - Permite padrões com curingas (* e #).
  - Uma única regra de binding pode atender várias Routing Keys.

  Curingas:

    *  → exatamente 1 segmento
    #  → zero ou mais segmentos


  --- Topic com * (order.*) ---

  Exchange : e.order.event
  Queues   : q.ticket.created
             q.ticket.deleted
  Binding  : order.*

  Comportamento — producer publica em e.order.event:

      order.created  → q.ticket.created  ✅
                       q.ticket.deleted  ✅

      order.deleted  → q.ticket.created  ✅
                       q.ticket.deleted  ✅

  O * exige exatamente um segmento depois de "order":

      order.created        → ✅  (1 segmento)
      order.deleted        → ✅  (1 segmento)
      order.updated        → ✅  (1 segmento)
      order                → ❌  (0 segmentos)
      order.created.email  → ❌  (2 segmentos)

  Exemplo visual:

      order.created
            │
            └── 1 segmento → corresponde a order.*

      order.created.email
            │       │
            └───────┴── 2 segmentos → NÃO corresponde a order.*


  --- Topic com # (orders.#) ---

  Exchange : orders.topic   (exemplo)
  Queue    : q.orders
  Binding  : orders.#

  O # aceita zero ou mais segmentos depois de "orders":

      orders               → ✅
      orders.created       → ✅
      orders.supply.create → ✅
      order.user.update    → ❌  (não começa com "orders")

  Exemplos típicos de Routing Keys:

      • orders.created
      • orders.updated
      • orders.cancelled


Headers Exchange

  - Não usa Routing Key. A decisão é feita pelos headers da mensagem.
  - É menos utilizada, mas muito flexível.

  Exemplo de headers:

      {
        region: "BR",
        priority: "HIGH"
      }


Responsabilidades da Exchange

  Ela faz:
    • Receber mensagens do Producer.
    • Consultar os Bindings.
    • Decidir o destino.
    • Encaminhar para uma ou mais filas.

  Ela não faz:
    • Processar mensagens.
    • Armazenar mensagens.
    • Entregar diretamente aos Consumers.
    • Confirmar processamento (isso é ACK entre Consumer e RabbitMQ).


Resumo dos tipos

  | Exchange | Como roteia?                     | Caso de uso                       |
  | -------- | -------------------------------- | --------------------------------- |
  | Direct   | Igualdade exata da Routing Key   | Filas específicas / work queue    |
  | Fanout   | Envia para todas as filas        | Broadcast e notificações          |
  | Topic    | Padrões com curingas (* e #)     | Eventos e microsserviços          |
  | Headers  | Baseado em headers               | Regras mais complexas             |
